# laptap

A daily geography game about ski mountains — a parody of [MapTap](https://maptap.gg/).

Five mountains a day, easiest first. You get a name, you tap the globe, and you score 0–100 on how
close you were. Rounds 3–5 are worth ×2, ×3 and ×3, so a perfect run is 1000.

```bash
npm install
npm run dev          # http://localhost:5188
```

## Question sets

| | pool | size | floors | repeats after |
|---|---|---|---|---|
| default | **Ikon Pass** — 73 destinations worldwide | 73 | country / continent | 14 days |
| `?pool=usa` | **All USA** — every US downhill area worth asking about | 497 | state / ski region | 49 days |

Each pool keeps its own daily result and streak, so playing one doesn't lock the other.

## Difficulty

The Ikon list is **hand-ranked by how well known each place is** — household names at the top
(Aspen, Jackson Hole, Zermatt), resorts only their own region has heard of at the bottom (Lutsen,
Granite Peak, Snowriver). That order *is* the difficulty curve: it's split into five equal tiers
and round N draws from tier N. The whole ranking lives in one place,
[`scripts/ikon-destinations.ts`](scripts/ikon-destinations.ts), and reordering it is the intended
way to tune the game.

The US pool is too big to hand-rank, so it's ordered by a size score instead (vertical drop
weighted highest — lift count alone puts a Michigan bump with twelve surface lifts above Alta).

## Scoring

Additive, so almost nothing scores zero. A round's base score (0–100) is the sum of:

| | global pool | US pool |
|---|---|---|
| right continent | **35** | right ski region **35** |
| right country | **+20** | — |
| right state | **+20** | right state **+40** |
| closeness | **up to +25** | up to +25 |

The rungs stack — a tap in Utah for Snowbird earns state, country *and* continent. Each rung is
also earned by landing within about 100 miles (300 for the continent), so a tap just across a
state line or a national border isn't punished, and destinations in countries without state
polygons can still reach the same maximum.

Closeness runs on a **log scale**, because that's how distance feels: 30 miles off versus 300 is
one step, 300 versus 3,000 another. It only reaches zero on the far side of the planet. Anything
within **3 miles** is a bullseye and scores a flat 100.

| global pool | base score |
|---|---|
| right state, 20 miles off | ~94 |
| right country, wrong state, 300 miles off | ~66 |
| right continent only, 1,000 miles off | ~43 |
| wrong continent, 5,000 miles off | ~3 |

A tap that lands in the sea or a lake snaps to the nearest land within about two degrees, so the
Great Lakes count as North America and the Ligurian Sea as Europe.

The rung points live on each pool in [`src/game/pools.ts`](src/game/pools.ts); the closeness
constants at the top of [`src/game/scoring.ts`](src/game/scoring.ts).

## Daily puzzles

Puzzle #1 was 2026-10-01. The day's five come from a fixed per-pool shuffle of each tier indexed
by the puzzle number, so everyone gets the same set with no server involved, and a mountain cannot
repeat until its whole tier has been used.

Add `?date=YYYY-MM-DD` to play any other day's puzzle — the only practical way to test without
waiting.

## The map

A spinning globe, like MapTap — MapLibre's globe projection over keyless Esri satellite tiles. It
rotates slowly while you read the prompt and stops the moment you touch it. No borders are drawn
anywhere: the boundary data still decides the scoring floors, but showing the lines would hand you
the country for free.

Zoom is capped at 11. Esri's imagery is a generalised green-and-white mosaic up to there and
switches to flat, hazy, dirt-coloured aerial photography at 12; stopping short keeps the whole game
looking like one map, and a screen at zoom 11 spans a few kilometres — far finer than the scoring
curve can tell apart.

**SATELLITE** is the default basemap; **ATLAS** is Esri's physical world map, a classic
green-and-tan atlas.

## The data

Everything under `src/data/` is generated by `npm run data`. Nothing there is hand-edited.

**Coordinates** come from [OpenSkiMap](https://openskimap.org/). Each Ikon destination is pinned
to an OpenSkiMap id rather than matched by name — fuzzy matching quietly mapped Tremblant to a
cross-country centre and three Japanese resorts to the same wrong hill. Linked areas (Dolomiti
Superski, Hakuba Valley) anchor to their best-known peak. Zermatt and Cervinia share one lift
system across the Swiss–Italian border, so each carries its own pinned coordinates and the build
checks they land in the right country.

**Boundaries** are Natural Earth 50m countries and `us-atlas` states, simplified through TopoJSON so
shared borders stay shared. The detail level is set by measurement: at `BOUNDARY_DETAIL = 0.3`
every destination lands in the right country for 186KB gzipped, while 0.2 shrinks Andorra until
Grandvalira falls into France.

The build hard-fails if any of that drifts — an id that stops resolving, a resort that geocodes
into the wrong country, a tier too small to avoid repeats, or any of six spot-checked coordinates
moving more than 0.05°.

## Layout

```
scripts/build-resorts.ts      ETL → src/data/*.json
scripts/ikon-destinations.ts  the ranked question list — edit this
src/game/                     pure logic: pools, scoring, daily selection, state machine, share
src/map/                      MapLibre globe and the pins/line drawn on top
src/ui/                       the cards and the terminal skin
```

No backend, no accounts, no secrets — `npm run build` emits a static `dist/`. Pools load their
resorts and boundaries through dynamic imports, so a player only downloads the set they're playing.

## Checks

```bash
npm test     # scoring curve, both floor schemes, daily determinism, no-repeat guarantee, pool shape
npm run build
```

## Tweaking it

- **Which mountains, and in what order** — [`scripts/ikon-destinations.ts`](scripts/ikon-destinations.ts), then `npm run data`.
- **Difficulty curve** — `DECAY_KM` in [`src/game/scoring.ts`](src/game/scoring.ts).
- **Snark** — the `SNARK` table in [`src/ui/cards.ts`](src/ui/cards.ts).
- **Colours** — custom properties on `:root` in [`src/ui/styles.css`](src/ui/styles.css).
- **A new pool** — add an entry to [`src/game/pools.ts`](src/game/pools.ts) and a builder in the ETL.
