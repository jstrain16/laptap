# laptap

A daily geography game about ski mountains — a parody of [MapTap](https://maptap.gg/).

Five mountains a day, easiest first. You get a name, you tap the map, and you score 0–100 on how
close you were. Later rounds are worth double and triple, so a perfect run is 1000.

```bash
npm install
npm run dev          # http://localhost:5188
```

## Question sets

| | pool | size | floors |
|---|---|---|---|
| default | **Ikon Pass** — the 80 global destinations | 80 | country / continent |
| `?pool=usa` | **All USA** — every US downhill area worth asking about | 497 | state / ski region |

Each pool keeps its own daily result and its own streak, so playing one doesn't lock the other.

## Scoring

| off by | 0 | 10km | 25km | 50km | 100km | 200km | 400km | 800km |
|---|---|---|---|---|---|---|---|---|
| score | 100 | 92 | 81 | 66 | 43 | 19 | 4 | 0 |

`100 · e^(−distance / DECAY_KM)`, with `DECAY_KM = 120`. That is the one knob worth turning if the
game plays too hard or too soft — it lives at the top of [`src/game/scoring.ts`](src/game/scoring.ts).

Two consolation floors soften a bad guess, mirroring MapTap's country/continent floors. What counts
as "close enough" depends on the pool: the global set floors on **country** (25) and **continent**
(10), the US set on **state** (25) and **ski region** (10). Floors only ever lift a weak guess,
never beat a close one. Round multipliers are `1, 1, 2, 3, 3`.

## Daily puzzles

Puzzle #1 was 2026-10-01. The day's five come from a fixed per-pool shuffle of each difficulty tier
indexed by the puzzle number, so everyone gets the same set with no server involved, and a mountain
cannot repeat until its whole tier is used — **16 days** for Ikon, 49 for the US pool.

Add `?date=YYYY-MM-DD` to play any other day's puzzle — the only practical way to test without
waiting.

## The data

Everything under `src/data/` is generated by `npm run data`. Nothing there is hand-edited.

**Mountains** come from [OpenSkiMap](https://openskimap.org/). The US pool is every operating
downhill area with at least one lift and 30m of vertical, ranked by a "would a skier have heard of
this" score:

```
fame = 1.0·ln(1+lifts) + 1.4·ln(1+verticalM) + 0.9·ln(1+runKm) + 0.8·(hasWikipediaEntry)
```

Vertical drop carries the most weight — lift count alone ranks a Michigan bump with twelve surface
lifts above Alta. The ranked list splits into five tiers; round N draws from tier N, so round 1 is
Vail and round 5 is a rope tow in Iowa. The Ikon pool is ranked the same way but split into even
fifths, since with only 80 destinations a skewed split would recycle tier 1 every week.

**The Ikon list** is transcribed from ikonpass.com in
[`scripts/ikon-destinations.ts`](scripts/ikon-destinations.ts), with each destination pinned to an
OpenSkiMap id rather than matched by name — fuzzy matching quietly mapped Tremblant to a
cross-country centre and three Japanese resorts to the same wrong hill. Entries that are groups of
mountains (SkiBig3, Dolomiti Superski, Valle d'Aosta, Niseko United) are anchored to their
best-known peak, noted inline.

**Boundaries** are Natural Earth 50m countries and `us-atlas` states, simplified through TopoJSON so
shared borders stay shared. The detail level is set by measurement, not taste: at `BOUNDARY_DETAIL
= 0.3` all 80 Ikon destinations land in the right country for 186KB gzipped, while 0.2 shrinks
Andorra until Grandvalira falls into France.

The build hard-fails if any of that drifts — a destination whose id stops resolving, a resort that
geocodes into the wrong country, a tier that gets too small to avoid repeats, or any of five
spot-checked coordinates moving more than 0.05°.

## Map

MapLibre over keyless Esri tiles, no API key and no place labels (a labelled basemap would show you
the answer). Two basemaps, toggled in the header:

- **SATELLITE** — the closest thing to MapTap's natural-earth globe texture.
- **ATLAS** — Esri's physical world map, a classic green-and-tan atlas.

Borders switch between light and dark with the basemap, since white hairlines vanish on a pale
atlas.

## Layout

```
scripts/build-resorts.ts    ETL → src/data/*.json
scripts/ikon-destinations.ts  the curated Ikon list
src/game/                   pure logic: pools, scoring, daily selection, state machine, share
src/map/                    MapLibre setup and the pins/line drawn on top
src/ui/                     the cards and the terminal skin
```

No backend, no accounts, no build-time secrets — `npm run build` emits a static `dist/`. The pools
load their resorts and boundaries through dynamic imports, so a player only downloads the set
they're playing.

## Checks

```bash
npm test     # scoring curve, both floor schemes, daily determinism, no-repeat guarantee, pool shape
npm run build
```

## Tweaking it

- **Difficulty** — `DECAY_KM` in [`src/game/scoring.ts`](src/game/scoring.ts).
- **Snark** — the `SNARK` table in [`src/ui/cards.ts`](src/ui/cards.ts), banded by distance.
- **Colours** — every one is a custom property on `:root` in [`src/ui/styles.css`](src/ui/styles.css).
- **A new pool** — add an entry to [`src/game/pools.ts`](src/game/pools.ts) and a builder in the ETL.
  Nothing else in the game knows which set it is serving.
